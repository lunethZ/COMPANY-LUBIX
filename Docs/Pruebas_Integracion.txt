PI-001 | Auth + Email + Usuarios | Registro y verificación
--------------------------------------------------------------------------------

  DESCRIPCIÓN:
    Verificar el flujo completo de registro de usuario: creación de
    cuenta, envío de código de verificación por email y verificación
    del código.

  DATOS DE ENTRADA:
    Registro: fullName='Juan Perez', email='juan@test.com',
    password='Password123', tell='3001234567'.
    Verificación: código de 6 dígitos recibido por email.

  RESULTADO ESPERADO:
    Usuario creado exitosamente. Código enviado por email. Verificación
    exitosa con código correcto. Usuario queda verificado.

  RESULTADO OBTENIDO:
    Pendiente de ejecución - Se requiere configurar SMTP y base de datos.

  ESTADO: Pendiente
  OBSERVACIONES:
    Se necesita cuenta SMTP configurada para envío de emails. Verificar
    que el servicio de email está operativo.


--------------------------------------------------------------------------------
PI-002 | Auth + JWT + Middleware | Login y acceso protegido
--------------------------------------------------------------------------------

  DESCRIPCIÓN:
    Verificar el flujo de login: validación de credenciales, generación
    de tokens JWT y acceso a rutas protegidas con el token.

  DATOS DE ENTRADA:
    Credenciales: email='juan@test.com', password='Password123'.
    Token: access_token del login.

  RESULTADO ESPERADO:
    Login exitoso con tokens válidos. Acceso a ruta protegida con token
    retorna datos del usuario.

  RESULTADO OBTENIDO:
    Pendiente de ejecución - Se requiere usuario verificado en BD.

  ESTADO: Pendiente
  OBSERVACIONES:
    El usuario debe estar registrado y verificado previamente. Los tokens
    tienen expiración (60min access, 7d refresh).


--------------------------------------------------------------------------------
PI-003 | Auth + JWT + Refresh Token | Rotación de tokens
--------------------------------------------------------------------------------

  DESCRIPCIÓN:
    Verificar el mecanismo de refresh token rotation: cuando el access
    token expira, el refresh token genera nuevos tokens y el anterior
    se revoca.

  DATOS DE ENTRADA:
    Access token expirado. Refresh token válido.

  RESULTADO ESPERADO:
    Nuevos tokens generados correctamente. Refresh token antiguo queda
    revocado en BD.

  RESULTADO OBTENIDO:
    Pendiente de ejecución - Se requiere manipular expiración de tokens.

  ESTADO: Pendiente
  OBSERVACIONES:
    El access token expira en 60 minutos. El refresh token en 7 días.
    La rotación genera nuevos tokens y revoca el anterior.

    no se pueda agregar si no hay stock disponible.

  DATOS DE ENTRADA:

  RESULTADO ESPERADO:
    Stock se decrementa al agregar al carrito. No se permite agregar

  RESULTADO OBTENIDO:

  ESTADO: Pendiente
  OBSERVACIONES:
    El stock se valida al momento de agregar al carrito. Si la cantidad
    solicitada excede el stock, se retorna error.
